## 二、今天使用的 Python 语法

### `pass`

用于暂时保留一个空代码块，例如只定义名称、暂时没有额外逻辑的自定义异常。

### 异常继承

```text
自定义异常继承 Exception
→ 可以被 raise 抛出
→ 可以被 try / except 捕获
```

### `raise` 与 `try / except`

```text
raise
→ 发现违规条件时主动抛出异常

try / except
→ 在调用方捕获并处理异常
```

异常捕获顺序应当从具体到通用：

```text
具体异常
→ 其他已知异常
→ Exception 兜底
```

宽泛的 `except Exception` 可能隐藏 `NameError` 等编程错误，因此只能作为最后防线。

### Guard Clause

遇到不合法状态时立即返回，减少多层 `if` 嵌套：

```text
路径不存在 → return
路径是目录 → return
路径不是普通文件 → return
条件全部通过 → 读取文件
```

### `append` 与 `extend`

```text
append(x)
→ 把 x 作为一个元素加入列表

extend(items)
→ 把 items 中的元素逐个加入列表
```

### 列表推导式

在一行中完成遍历、筛选和转换：

```python
[f"{item.name}/" for item in items if item.is_dir()]
```

### `with` 上下文管理器

`with open(...)` 会在离开代码块时自动关闭文件，即使读取过程中发生异常，也能正确释放文件资源。

### `Path / 子路径`

`pathlib.Path` 使用 `/` 拼接路径，比手工拼接字符串更清晰，并能跨平台处理路径。

### f-string

使用 `{变量}` 把数据放入字符串，适合构造清晰的成功或错误信息。

### Truthiness

空列表为假，非空列表为真：

```text
if folders:
→ folders 中存在内容时执行
```

### 联合类型 `|`

Python 3.10+ 可以使用：

```text
str | Path
```

表示参数可以是字符串或 `Path` 对象。类型注解主要用于阅读、编辑器提示和静态检查，不会自动完成运行时类型验证。

## 三、今天修复的问题

### 1. 缩进错误

`list_files` 中 `try`、条件判断和 `except` 的缩进层级不一致，导致整个文件无法解析。

### 2. `Path` 大小写错误

`pathlib` 提供的是大写的 `Path` 类，不是小写 `path`。

### 3. 变量名不一致

函数参数与内部使用的 `user_path` 名称不一致，导致 `NameError`。同时避免使用参数名 `Path`，防止覆盖导入的 `Path` 类。

### 4. 函数契约不一致

统一使用 `list_files`，测试调用时同时传入：

```text
workspace
dir_path = "."
```

其中 `"."` 表示工作区根目录。

### 5. 返回格式不一致

将目录标题统一为：

```text
[文件夹]
[文件]
```

### 6. 越界错误不明确

越界异常统一包含稳定关键词 `越界访问`，方便用户理解，也方便测试判断。

## 四、今天理解的安全边界

文件工具不能直接信任 LLM 或用户传入的路径。

```text
workspace
→ Agent 被允许操作的根目录

user_path
→ 尚未验证的用户路径

final_path
→ 解析后的最终绝对路径
```

只有当 `final_path` 位于 `workspace` 内时，工具才允许继续操作。

这层检查需要由本地 Python 代码强制执行，不能只依赖 Prompt 告诉 LLM“不要越界”。
